# 单元测试

只测不依赖浏览器的纯逻辑模块，使用 Node 自带的测试运行器，不引入额外依赖。

```sh
npm test
```

## 目录约定

- 目录结构与 `src/` 对应：`src/utils/time.js` 的测试是 `tests/utils/time.test.js`。
- 测试文件以 `.test.js` 结尾，运行器据此自动发现。
- `helpers/` 放多个测试共用的数据与工具，不以 `.test.js` 结尾。

## 当前覆盖

`features/contest/rating-prediction/algorithm/` 下：

- `fft.js`：卷积结果、容量与空输入。
- `calculator.js`：输入校验、并列名次、预期名次、涨跌分性质、表现分。
- `analysis.js`：完整结算、按名次与按评级分析、错误码。
- `curve.js`：取样名次、取样点整理、按曲线估算评级与名次，以及取样曲线与精确结果的一致性。
- `ranks.js`：档位边界、晋级判断。
- `newcomer.js`：新号规则：按这一场在评级记录里排第几判断前六场、第七场起不修正、进行中的比赛和记录里没有这一场时怎么数、老规则时期不修正，以及显示评级与实际评级的互相换算。
- `team-rating.js`：队伍评级：一个人的队就是他自己的评级、两人队对照 VK Cup 的实际数值、与队员先后无关且不低于最强的队员。

`features/contest/rating-prediction/` 下：

- `trusted.js`：哪些比赛有可信参赛者的规则；按提交记录逐题统计并算 ICPC 成绩（哪些提交不罚时、通过之后不再算）；接着上次扫时的并入（分几次和一次的结果一致、还在评测的提交下次重读、回头等的上限）。
- `api-reply.js`：接口回复的归类：答 OK 取结果、接口自己报错算业务错误并带上原因、正文读不出来算网络错误；只有「没有评级变化」才当成没出分或不计分。
- `official.js`：官方评级记录合成参赛者：个人赛一条记录一个人；团队计分一支队合成一个、评级取队伍评级；队里有人没有记录或同队涨跌分不一致时不合；新号规则之后的首场账号按 1400 算；这一场计不计分的判断。
- `rating-lookup.js`：赛前评级的取法（上一次快照、名单、按账号查到的，依次取）、哪些人还要按账号去查、查到的结果对回账号、从报错里认出查不到的账号。
- `standings/native-actions.js`：哪些格子挂着原站的操作：页面载入时就带题目编号的格子和选手格算，之后才有的、同步时整格新加的不算。
- `standings/page-scores.js`：从页面上的榜单读成绩（按分数算的、ICPC 赛制的、「=」后面直接是题目的），哪些行不读，以及把快照里这些人的成绩换成页面上的、其余不动。
- `standings/team-rows.js`：队伍的行按队员账号对上记录、对不上的情况、什么时候断定队伍不计分、队名里的星号、队伍人数，以及计分队伍按成员分开和不分的情况。
- `standings/table-sync.js`：榜单表格的对账（用一个假表格）：成绩变了的格子留着原来的格子只改属性和内容、行按新名次排、新行加入旧行去掉、隔行底色和边线按新位置重加。

`features/user/analytics/` 下：

- `pack.js`：提交记录的压缩：排序、剔除训练营、序号表、队伍与赛中时间标记、题库外题目的附带信息、结构检查。
- `stats.js`：难度分归档、逐题汇总与尝试次数、并行场次计数、队伍提交开关、最长连续天数、统计摘要、难度分布、标签分布；按天汇总通过的题与重做的题（热力图）、月度活跃度、近期平均难度、未解决题目；语言、提交结果、尝试次数、参赛类型四种分布（参赛类型每种再分个人和队伍），比赛速度、刷题作息（含时间跨度）、标签弱项、难度分纵轴的范围与间隔；按指定时区算月份。
- `rating-history.js`：评级历史的压缩（排序、每场一行、比赛名称另放）、结构检查、按时刻找最近的一场、比赛归类（Div. 1 到 Div. 4 与其余，合并场按赛前的评级归）、名次轴的刻度。
- `store.js`：各账号的数据集与评级历史合存在一个键里的结构：读入时的整理、旧数据并入、超出数量时去掉谁、查看存储时的缩略版。
- `languages.js`：把原站的语言名称并成语言（不同版本、编译器算一种），认不出的去掉版本号后保留。

`features/user/avatars/` 下：

- `team-members.js`：队伍成员的读取：从「...」的提示里读出被原站折叠的账号、不是账号的内容不算、头衔换成原站的颜色类名和提示，以及 Ghost 队伍几种写法的成员名单。

`features/user/groups/` 下：

- `store.js`：用户分组的结构：残缺内容的整理、各登录账号分开存；新建、修改、删除分组和调整先后（「好友」固定在最前，名字不能改）；加人、移出；一个人在几个分组里时标记和头像框各取哪个；标记按看得见的字符算、宽的字符只画第一个；备注只给在分组里的人；好友名单整份替换、关注与取消关注；认出改过名的账号（回复的先后对不上时一个都不认）、成员改名时合并记录、登录账号自己改名时整份挪动。
- `reorder.js`：拖动调整分组先后时要不要和相邻的一行换位（过了中线才换、一次一格、换得到首尾、停在线附近不来回换、行高不一样时也稳），以及拖的过程中列表照临时的先后怎么排。
- `friends.js`：从原站好友页的源码里读出好友名单（名字和原站的用户编号），哪些行不算，以及认出是不是这个账号登录着时的页面；从个人主页的源码里读出关注用的那颗星（名字、编号、关注了没有）。

`features/general/` 下：

- `release-notes.js`：从更新日志文档里读出各版本的分类与条目（中英文分类、认不出的分类、空版本、错误页）；一条内容拆成文字、代码和链接，网页代码与不是网址的链接留作文字；并核对 `docs/` 里两份更新日志最新版本的内容与菜单里的更新日志一致。

`features/appearance/verdicts/` 下：

- `test-info.js`：从判题文字里找出测试点信息：编号在同一段里、编号在后面的节点里、俄文界面，以及没有测试点信息的文字。

`features/appearance/time/` 下：

- `format.js`：悬停提示文字里原站写法的时间按设置的格式改写，时区和其余文字保留；关闭时间格式化后不改写。

`features/page/` 下：

- `theme.js`：深浅色判断在同一段同步代码里只做一次，之后重新判断。测试里用假对象顶替页面。
- `plugin-ui.js`：悬停提示、菜单、弹窗、数据分析面板算插件自己的界面，原站页面不算；页面增强据此跳过它们。

`i18n/` 下：

- `locales/`：各份界面文字的词条一一对应（哪种语言都不缺、同一条在各语言里都是文字或都是函数、文字不为空）。少一条时界面不报错，只会悄悄拿另一种语言的顶上，所以在这里查。新增语言文件后自动纳入检查。
- `tags/`：每种语言的题目标签译名表都覆盖原站现有的全部标签，没有多余的键，译名非空且互不重复。新增语言文件后自动纳入检查。

`utils/` 下：

- `utils/time.js`：时间格式占位符、时区标注。
- `utils/problem.js`：题号排序、标题清理、链接解析、由题号拼出题目页地址。
- `utils/row-toggle.js`：设置行整行点击。
- `utils/text-overflow.js`：判断文字是否被省略，宽度带小数、正好放满时不误判。
- `utils/backdrop.js`：点遮罩关闭弹窗，按下与松开不在同一处时不关闭。
- `utils/color.js`：两种颜色按比例相混。
- `utils/json.js`：写成带缩进的 JSON 文字时，纯数字的数组各占一行；给预览用的缩略版（小数据不截，大数据每层只留开头几项、总量有上限、小记录不拆开）。
- `utils/language-wave.js`：换语言的逐项波浪里，各项晚多久开始（项多了间隔变短，总时长有上限）。认界面、认项和过渡本身要在页面上跑，不在这里测。
- `utils/fingerprint.js`：文字的指纹：同样的文字指纹相同、长度变了就变；短文字每个字符都读，长文字只读开头、结尾和均匀抽的位置，没被读到的位置改了看不出来（已知的盲区）。
- `utils/petal-palette.js`：页签在花瓣色环上的位置与取色，把一组颜色统一到同一明度，以及把一个颜色放回色环上它原来的位置；并核对十个页签图标里写的颜色与取色结果一致，增删页签或调整顺序后会指出该改成什么颜色。

`src/` 根目录下：

- `settings.js`：别的标签页保存设置后本页原地更新、通知各功能且不写回；本页自己的写入不触发；同步后再保存不会盖掉对方的修改；脚本管理器没有通知接口时不报错。老用户旧键里的旧结构设置载入后每一项都带到新结构、写进新键，旧键原样不动；升级时还开着的旧版本页面改写旧键不影响本页；类型或取值不对的项落回默认值；预测缓存的比赛场数比上限大时收到上限；新加的快捷键不抢已占用的键；按路径修改与恢复默认。测试里用一张表顶替油猴存储。

`config/` 下：

- `config/defaults.js`：默认设置第一层只有结构版本号和各页签的分组；扫描 `src/` 里读写的每一条设置路径，核对默认设置里都有。

`storage/` 下：

- `storage/runtime.js`：插件数据的合并、迁移、按字段读写与清空。测试里用一张表顶替油猴存储。
- `storage/migrations/settings.js`：旧结构设置改写成按页签归档的结构：各项的去向、缺失项留空、高亮色与透明度合并、语言图标像素值换算、CList 同步时间挪到插件数据、旧默认快捷键替换。

`helpers/` 里的 `legacy-settings.js` 是一份每项都取非默认值的旧结构设置和它迁移后的样子，上面两处测试共用；旧结构之后才加的设置项另列一张表（`ADDED_LATER`），载入后取默认值（`loadedSettings`）。

`ui/pages/changelog/` 下：

- `data.js`：各版本的时间戳齐全、从新到旧排列，并与行尾注释里的北京时间一致。

`ui/pages/groups/` 下：

- `drag-structure.test.js`：分组页拖动依赖的页面结构还在不在（行的两层结构、列表是定位容器、按排好的位置量相邻的行、用指针事件和挡板、松手才存）。这里拖不了，只核对源码；不过的话说明改到了拖动依赖的东西，要在浏览器里实际拖一遍。

`styles/` 下：

- `tokens.css`：检查 `src/ui/` 的组件是否绕过设计变量直接写灰阶色值，或直接写等于变量数值的字号、圆角、字重；字号是否都是整数像素；并检查引用的变量都已定义。

## 不在范围内

- 依赖页面 DOM、油猴接口或网络的模块。
- Vue 组件与视觉效果，由人工在浏览器中验收。
